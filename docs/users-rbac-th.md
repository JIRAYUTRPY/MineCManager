# บัญชีผู้ใช้และสิทธิ์ของ Panel

## เปิดใช้ครั้งแรก

1. เปิด Panel ผ่าน HTTPS หรือผ่าน SSH tunnel ที่ `http://127.0.0.1:9080` ระบบพาไป `/setup` ทั้งการติดตั้งใหม่และการอัปเกรดจากรุ่นที่ยังไม่มีบัญชี
2. อ่าน admin key ที่ Panel VM ด้วยคำสั่งตามวิธีติดตั้งด้านล่าง กรอก key บนหน้า setup พร้อมชื่อผู้ดูแลและรหัสผ่านอย่างน้อย 12 ตัวอักษร แล้วกด **สร้างบัญชีผู้ดูแล**
3. หลังจากสร้างสำเร็จ ทุกคนเข้าผ่าน `/login` ด้วยชื่อผู้ใช้และรหัสผ่านของตัวเอง การเปิด `/setup` อีกครั้งจะพาไปหน้าเข้าสู่ระบบหรือหน้าหลัก

| วิธีติดตั้ง | อ่าน admin key บน Panel VM | ไฟล์บัญชี |
|---|---|---|
| `setup.py panel` | `sudo cat /var/lib/mcm-managed-panel/admin-key.txt` | `/var/lib/mcm-managed-panel/accounts.sqlite3` |
| Docker Compose | `docker compose exec panel cat /data/admin-key.txt` | `/data/accounts.sqlite3` ใน volume `panel-data` |
| systemd ตามคู่มือติดตั้งด้วยตนเอง | `sudo cat /root/mcm-bootstrap.key` | `/var/lib/mcm-panel/accounts.sqlite3` |

ชื่อผู้ใช้ยาว 2–40 ตัว เริ่มด้วยอักษรอังกฤษ ตามด้วยอักษรอังกฤษ ตัวเลข `_` หรือ `-` ระบบเก็บชื่อเป็นตัวพิมพ์เล็ก ธุรกรรม SQLite บันทึกทั้งบัญชีผู้ดูแลและสถานะเปิดใช้งานพร้อมกัน หากผู้ดูแลสองคนส่งฟอร์มพร้อมกัน จะสร้างสำเร็จเพียงคำขอเดียว

สำหรับ Panel เดิม ระบบตรวจ key ID `bootstrap` หรือ `bootstrap-admin` ที่ยังใช้งานได้และมี `admin:keys` หากเคยหมุนหรือเปลี่ยนชื่อ key ก่อนอัปเกรด ให้ตั้ง `MCM_BOOTSTRAP_KEY_ID` เป็น ID ของ key ผู้ดูแลที่ถืออยู่ แล้วรีสตาร์ต Panel ก่อนเปิดใช้ครั้งแรก ตัวแปรนี้ไม่มีผลต่อบัญชีที่สร้างสำเร็จแล้ว เก็บรหัสผ่านผู้ดูแลใน password manager เพราะ key ใช้สร้างบัญชีซ้ำหรือรีเซ็ตรหัสผ่านผู้ดูแลไม่ได้

## ให้สิทธิ์ทีม

ผู้ดูแลเปิด **ผู้ดูแล → ผู้ใช้** (`/admin/users`) กรอกชื่อ ตั้งรหัสผ่านเริ่มต้น และเลือกหนึ่งบทบาทต่อบัญชี ผู้ใช้เปลี่ยนรหัสผ่านเองได้ที่ **บัญชีของฉัน** (`/account`) ผู้ดูแลแก้บทบาท ตั้งรหัสผ่านใหม่ หรือปิดบัญชีทีมได้จากตาราง เมื่อแก้บัญชี เซสชันเดิมของบัญชีนั้นหมดสิทธิ์ทันที

| บทบาท | ทำอะไรได้ |
|---|---|
| `admin` | บัญชีเดียวที่สร้างตอน setup ดูแลผู้ใช้ บทบาท key ทะเบียน Agent และ Fleet ทั้งหมด รวมถึงงานระดับ root บน VM |
| `viewer` | ดูสถานะ node รายการปลั๊กอิน รายการสำเนา ผู้เล่นออนไลน์ และสถิติทรัพยากร |
| `operator` | สิทธิ์ของ viewer เพิ่มการควบคุมบริการ แก้ config จัดการปลั๊กอิน สร้างสำเนา และอ่าน inventory |
| กำหนดเอง | เลือก scope สำหรับงานที่มอบหมาย เช่น `nodes:read` และ `players:read` สำหรับทีมที่ต้องดูรายชื่อผู้เล่น |

เปิด **ผู้ดูแล → บทบาทและสิทธิ์** (`/admin/roles`) เพื่อสร้างหรือแก้บทบาทที่กำหนดเอง บทบาทระบบมีชุดสิทธิ์ตายตัว เมนูแสดงตามสิทธิ์ และ Panel ตรวจสิทธิ์อีกครั้งเมื่อเปิด URL หรือเรียก API การแก้ scope ของบทบาทมีผลกับคำขอถัดไปของผู้ใช้ทุกคนในบทบาทนั้น สิทธิ์ของบัญชีทีมครอบคลุม node ที่ลงทะเบียนทั้งหมด การให้สิทธิ์ระดับเครื่องเฉพาะตัวสำหรับ integration ใช้ node restriction ของ API key ได้

สิทธิ์ `admin:*` และ `users:manage` สงวนให้ผู้ดูแลคนแรก ส่วน `audit:read` เปิดประวัติรวมทั้ง Panel จึงควรเลือกให้เฉพาะบทบาทที่อ่านประวัติทุกเครื่องได้ การตรวจ inventory หรือแทนที่ item จากเว็บใช้ `inventory:read` และการเขียนเพิ่ม `inventory:write` ส่วนการแก้ config ผ่านเว็บต้องอ่านเนื้อหาและเวอร์ชันก่อน จึงต้องมีทั้ง `configs:read` และ `configs:write`

## หน้าเว็บและค่าที่จำ

| หน้า | ตัวอย่างค่าที่เก็บแยกตามผู้ใช้ |
|---|---|
| `/nodes`, `/nodes/plugins`, `/nodes/config`, `/nodes/backups` | node ที่เลือกล่าสุดของแต่ละหน้า |
| `/nodes/players` | node และ UUID ของผู้เล่น |
| `/fleet`, `/fleet/minecraft`, `/fleet/files`, `/fleet/backups` | VM ที่เลือกในแต่ละหน้า รวมถึง Server ID, platform หรือ service ในหน้าที่รองรับ |
| `/fleet/jobs`, `/fleet/updates`, `/fleet/cloud` | ตัวกรองสถานะงาน เป้าหมายการอัปเดต หรือชนิด DNS record |
| `/admin/users`, `/admin/roles` | ตัวกรองบทบาทหรือบทบาทที่เลือกดู |

SQLite อยู่ข้าง `MCM_PANEL_CONFIG` โดยปริยาย เปลี่ยนพาธด้วย `MCM_ACCOUNTS_DB` โดยให้ service เขียนไดเรกทอรีนั้นได้ Panel อ่านค่าที่เลือกจาก SQLite เมื่อเปิดหน้าอีกครั้ง รวมถึงเมื่อผู้ใช้ล็อกอินจากเบราว์เซอร์ใหม่ ฐานนี้เก็บบัญชี ตัวตรวจรหัสผ่านแบบ Argon2id บทบาท สิทธิ์ เซสชัน และค่าที่อนุญาตของแต่ละหน้า ส่วน SSH credentials, งาน และ schedule อยู่ใน Fleet vault ตามเดิม ข้อความใน editor, รหัสผ่านที่กรอก และ API token ไม่ถูกบันทึกเป็นค่าของหน้า

สำรองข้อมูลโดยหยุด Panel แล้วคัดลอกไดเรกทอรีข้อมูลทั้งชุด พร้อมไฟล์ config และ secrets ที่ใช้กู้คืน เมื่อย้าย VM ให้คืน `accounts.sqlite3` พร้อมข้อมูลชุดนั้นก่อนเริ่ม Panel ตั้งเจ้าของไฟล์เป็นผู้ใช้ service และสิทธิ์ไฟล์เป็น `0600` ถ้าตั้ง `MCM_ACCOUNTS_DB` ไว้ภายนอก อย่าลืมสำรองพาธนั้น ข้อมูลการเปิดใช้ครั้งแรกอยู่ในฐานนี้ การคืนฐานเก่าจะคืนสิทธิ์และข้อมูลเซสชัน ณ เวลาที่สำรองด้วย

## API และ audit

| เส้นทาง | งาน |
|---|---|
| `GET /v1/auth/session` | ดู `needs_setup` และผู้ใช้ปัจจุบัน |
| `POST /v1/auth/bootstrap`, `POST /v1/auth/login`, `POST /v1/auth/logout` | เปิดใช้ เข้าสู่ระบบ และออกจากระบบ |
| `POST /v1/me/password` | เปลี่ยนรหัสผ่านตัวเองและเพิกถอนเซสชันของบัญชี |
| `GET` / `PUT /v1/me/preferences/{page}` | อ่านหรือบันทึกเฉพาะฟิลด์ของหน้านั้นสำหรับบัญชีปัจจุบัน |
| `GET` / `POST /v1/manage/users`, `PATCH /v1/manage/users/{username}` | ดู สร้าง แก้ไข หรือปิดบัญชี |
| `GET` / `POST /v1/manage/roles`, `PUT /v1/manage/roles/{name}` | ดู สร้าง หรือแก้ไขบทบาท |

Panel ออก cookie `mcm_session` อายุ 12 ชั่วโมง พร้อม `HttpOnly` และ `SameSite=Strict` บนโดเมนสาธารณะใช้ HTTPS และให้ reverse proxy ส่ง Host ของ Panel มาด้วย การเขียนจากเว็บต้องมาจาก origin ของ Panel และมี header `X-MCM-Request: 1` การทำงานจากบัญชีเว็บปรากฏใน audit ด้วย `user:<username>`

Agent, การจับคู่ด้วย `setup.py pair` และ integration ที่ใช้ `Authorization: Bearer` เดิมยังทำงานด้วย API key ของแต่ละงาน ผู้ดูแลจัดการ key ที่ `/admin/keys` และทะเบียน Agent ที่ `/admin/nodes` การออกจากเว็บไม่ยกเลิก API key ที่ออกให้ระบบอื่น [OpenAPI ของ Panel](../api/openapi.yaml)
